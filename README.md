# Чат-приложение в реальном времени

Fullstack-приложение для обмена сообщениями в реальном времени, разработанное на **React**, **Node.js**, **TypeScript**, **MySQL**, **WebSocket** и **Docker**.

Проект представляет собой веб-мессенджер по типу Telegram Web / WhatsApp Web с регистрацией пользователей, авторизацией, приватными диалогами, realtime-доставкой сообщений, отображением online/offline статуса пользователей, поиском пользователей и сохранением истории переписки в базе данных.

Весь стек приложения контейнеризирован и запускается одной командой через Docker Compose.

## О проекте

Цель проекта — реализовать полноценное fullstack-приложение, демонстрирующее работу с realtime-коммуникацией, авторизацией, REST API, WebSocket, реляционной базой данных, backend-валидацией и Docker-инфраструктурой.

Приложение построено как SPA-интерфейс мессенджера, где пользователь может зарегистрироваться, войти в аккаунт, найти другого пользователя и начать приватную переписку.

## Архитектура приложения

Приложение состоит из трёх основных сервисов:

- **Frontend** — React SPA, отвечающая за пользовательский интерфейс и клиентскую логику.
- **Backend** — Node.js сервер, который обрабатывает авторизацию, REST API-запросы, бизнес-логику, валидацию и WebSocket-события.
- **Database** — MySQL-контейнер для хранения пользователей, диалогов и сообщений.

Frontend взаимодействует с backend двумя способами:

- через **REST API** — для авторизации, поиска пользователей, загрузки данных и обычных request-response операций;
- через **WebSocket** — для realtime-доставки новых сообщений и обновления online/offline статусов.

## Как работает отправка сообщений

1. Пользователь входит в аккаунт.
2. Frontend устанавливает WebSocket-соединение с backend.
3. Backend определяет подключённого пользователя и обновляет его online-статус.
4. Пользователь отправляет сообщение в приватный диалог.
5. Backend валидирует сообщение и сохраняет его в MySQL.
6. Если получатель находится онлайн, backend отправляет ему новое сообщение через WebSocket.
7. Сообщение появляется у получателя без обновления страницы.
8. При отключении пользователя его статус обновляется на offline.

## База данных

В качестве основной базы данных используется MySQL.

В базе хранятся:

- пользователи;
- данные авторизации/сессий;
- приватные диалоги;
- сообщения.

Проект использует чистый SQL без ORM, что даёт прямой контроль над структурой запросов, работой с таблицами и логикой получения данных.

## WebSocket

WebSocket используется для realtime-возможностей приложения:

- доставка новых сообщений;
- обновление online-статуса пользователя;
- обновление offline-статуса пользователя;
- live-обновление активного диалога.

REST API и WebSocket используются совместно: REST API отвечает за стандартные запросы, а WebSocket — за события, которые должны обновляться в реальном времени.
